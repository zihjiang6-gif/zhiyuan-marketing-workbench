## 1. 项目概述

**知源营销工作台**是一个基于浏览器的 AI 营销内容运营工作台原型。帮助品牌营销和内容运营团队从一份产品简报出发，生成平台特定的营销内容（小红书、微信、LinkedIn），整个过程以结构化知识库为基础——配合内容质检机制（AI Guardrails）、人工审核、版本历史与投放效果反馈。

**这不是一个 ChatGPT 套壳工具。** 它展示了一个完整的产品工作流：知识导入 → 检索 → 提示词构建 → 内容生成 → 内容质检 → 人工审核 → 导出 → 效果回写。

---

## 2. 问题定义

营销团队在生产跨平台内容时面临五个持续挑战：

1. **跨平台生产缓慢** — 为小红书、微信和 LinkedIn 撰写平台适配文案，每套内容需 2-4 小时。
2. **品牌调性不一致** — 不同文案人员产出的语调不统一；品牌规范难以在规模化生产中贯彻。
3. **知识孤岛** — 产品信息、品牌规范和过往活动经验散落在不同文档和团队成员脑中。
4. **AI 输出不可控** — 通用大模型输出缺乏品牌根基、来源可追溯性和内容质检机制。
5. **审核流程缺失** — 从草稿到发布之间缺乏结构化的审批流程。

## 3. 目标用户

| 角色 | 痛点 | 需求 | 平台如何解决 |
|------|------|------|-------------|
| **营销执行** | 写三平台文案需数小时 | 快速生成初稿 | 一份简报 → 约 18 分钟产出三平台内容 |
| **品牌经理** | 无法确保不同写手的调性一致性 | 可执行的品牌规则 | 基于知识库生成 + 品牌调性内容质检 |
| **内容运营** | 无法复用过往经验 | 历史知识检索 | RAG 检索产品信息、历史案例 |
| **设计师** | 不清楚各平台视觉方向 | 平台特定的视觉提示词 | 各平台独立的 SDXL + ControlNet 指令 |
| **营销总监** | 无法衡量内容质量和 ROI | 质量指标 + 效果反馈 | 质量评分、审核追踪、学习回写闭环 |

## 4. 核心场景

**新品上市流程：**

营销运营人员收到产品简报 → 输入平台 → 系统从知识库检索相关信息 → 构建结构化提示词 → 生成小红书、微信、LinkedIn 内容 → 运行内容质检 → 运营人员审核通过 → 导出活动包 → （投放后）查看效果反馈 → 将高表现内容回写至知识库。

## 5. MVP 范围

### 已包含（当前原型）
- 知识库导入（JSON、CSV、粘贴、URL、手动）
- 可编辑的营销活动简报输入
- 知识检索（关键词 + 权重匹配，RAG 模拟）
- 结构化提示词构建面板
- 多渠道内容生成（小红书、微信、LinkedIn）
- 视觉提示词 + ControlNet 指令生成
- 内容质检面板（事实准确性、违规宣称、品牌调性偏离、平台适配）
- 人工审核工作流（通过/驳回/编辑/重新生成）
- 版本历史 + 活动时间线
- 可解释的质量评分指标
- 导出活动包（JSON + Markdown 下载）
- 投放效果反馈模拟 + 学习回写
- 运营仪表盘总览

### 明确不包含
- 真实 OpenAI / LLM API 集成（前端模拟）
- 真实平台发布
- 用户认证 / 团队角色
- 向量数据库（以加权关键词匹配模拟）
- 真实图片生成
- 后端数据库持久化（仅 localStorage + JSON 文件）

## 7. 系统架构

### 当前原型
```
浏览器 (index.html / import.html)
  ├── localStorage（用户导入的知识）
  ├── JSON 兜底 (data/knowledge_base.json)
  ├── JavaScript 检索模拟（关键词 + 加权评分）
  ├── JavaScript 生成模拟（基于模板）
  └── 可选: Express 服务 (server.js) 用于 API 模式
```

### 生产架构
```
前端: React / Next.js
后端: Node.js / Python FastAPI
数据库: PostgreSQL（结构化活动记录）
向量库: Pinecone / pgvector（语义检索）
大模型层: OpenAI / Claude API
图像层: SDXL / DALL-E with ControlNet
工作流: 审核状态、版本控制、导出日志
分析层: 平台效果数据集成
```

## 8. 为什么不是 ChatGPT 套壳

本平台在 7 个关键维度上区别于简单的 ChatGPT 提示：

1. **知识导入** — 结构化知识记录，带分类、可信度和权重
2. **来源可追溯** — 每句生成内容都可追溯到知识记录
3. **结构化提示词构建** — 系统角色 + 产品信息 + 品牌规则 + 平台规则 + 合规规则
4. **多平台适配** — 平台特定的风格规则，而非单一通用输出
5. **内容质检机制（AI Guardrails）** — 事实准确性检查、违规宣称检测、品牌调性偏离监控
6. **人机协同** — 草稿 → 审核 → 通过/驳回 → 版本历史工作流
7. **反馈闭环** — 投放后效果数据回写至知识库

## 9. 指标体系

### 生成质量指标
| 指标 | 描述 | 计算方式 |
|------|------|---------|
| **事实准确性** | 知识库事实正确引用比例 | 匹配事实数 / 需检查事实数 - 违规扣分 |
| **品牌一致性** | 调性匹配品牌规范程度 | 正面调性词检测 - 禁用表达扣分 |
| **平台适配度** | 内容匹配平台风格规则 | 平台特定规则检查（小红书: hashtag、emoji；微信: 结构；LinkedIn: 专业度） |
| **可编辑性** | 需要多少人工修改 | 以内容质检通过率衡量 |
| **合规风险** | 监管/宣称问题风险 | 越低越好 — 未经证实的宣称计入风险 |

### 业务影响指标
| 指标 | 值（模拟） | 描述 |
|------|---------|------|
| **初稿时间** | 18 分钟 | 从输入简报到三平台初稿 |
| **单套内容成本** | 约 ¥35（预估） | 三平台大模型 API 费用 |
| **通过率** | 78% | 生成内容无需重新生成即通过 |
| **重写率** | 22% | 需要至少一次重新生成的内容 |
| **周内容产出** | 8-12 套 | 每位运营人员预估周产出 |
| **预估节省时间** | 约 70% | 对比人工各平台撰写 |

## 10. 运行方式

### 方式 A: 静态文件（仅浏览器，localStorage 模式）
```bash
# 直接在浏览器打开
open index.html
open import.html
open dashboard-zh.html
```

### 方式 B: 使用本地服务器（推荐，支持 JSON 文件加载）
```bash
cd "知源营销平台/v2"
python3 -m http.server 8000
# 然后在浏览器打开 http://localhost:8000/index.html
```

### 方式 C: 后端 API 模式（下一阶段）
```bash
# 当前 v2 目录暂未包含 server.js / package.json。
# 后续可补充 Express 或 FastAPI 后端，用于真实 API、向量检索和团队协作。
```
